# 사전신청 폼 백엔드 (Google Sheet + Apps Script)

신청 데이터를 **내 Google Sheet**에 직접 쌓고, 신청이 들어오면 메일로도 알림을 받는 설정.
제3자 서비스를 거치지 않아 개인정보(전화번호)가 내 구글 계정 안에만 저장됩니다.

폼은 `Content-Type: text/plain`으로 전송해 CORS preflight를 피하고, Apps Script 웹 앱의
응답을 정상적으로 읽어 성공/실패를 분기합니다.

---

## 먼저 정할 것 — 새 시트 vs dionomy 시트 재활용

들리 폼은 payload에 `form: "deulli"`를 실어 보냅니다. 아래 스크립트는 그 값으로
**탭(시트)을 골라** 기록하므로, 두 방식 다 같은 클라이언트 코드로 동작합니다.

|                        | 새 스프레드시트               | dionomy 스프레드시트 재활용  |
| ---------------------- | ----------------------------- | ---------------------------- |
| 작업량                 | 시트·스크립트·배포를 새로 1회 | 기존 스크립트 교체 후 재배포 |
| dionomy 라이브 폼      | 건드리지 않음                 | 재배포 실수 시 같이 멈춤     |
| 개인정보 분리          | 서비스 단위로 깔끔            | 파일은 같고 탭만 다름        |
| `PUBLIC_FORM_ENDPOINT` | 들리 전용 URL                 | dionomy와 동일 URL 재사용    |

**같은 탭에 섞는 것만은 하지 마세요.** dionomy는 `이름·스튜디오·연락처·카테고리·기타·동의`
6컬럼인데 들리는 전화번호 하나라 빈 칸이 줄줄이 남고, 무엇보다 개인정보 **동의 범위와
보유 기간이 서로 달라** 나중에 "들리 신청자만 파기"가 불가능해집니다.

권장은 **새 스프레드시트**입니다. 아래 1~5단계가 5분이면 끝나고, 운영 중인 dionomy 폼을
전혀 건드리지 않습니다. 재활용을 택했다면 2단계에서 기존 프로젝트의 `Code.gs`를 아래 코드로
교체하고, 5단계에서 **새 버전으로 재배포**만 하면 됩니다 — dionomy 폼은 `form` 값이 없어서
`SHEETS.default` 규칙을 타고 기존과 동일하게 동작합니다.

---

## 1. Google Sheet 만들기

1. [sheets.new](https://sheets.new) 로 새 스프레드시트 생성 (예: `들리 사전신청`)
2. 탭 이름을 `deulli`로 바꿉니다. (아래 스크립트의 `SHEETS.deulli.tab`과 같아야 합니다.
   탭이 없으면 스크립트가 자동으로 만들고 헤더까지 넣습니다.)

## 2. Apps Script 코드 붙여넣기

1. 시트 상단 메뉴 **확장 프로그램 → Apps Script**
2. 기본 `Code.gs` 내용을 [`apps-script/Code.gs`](../apps-script/Code.gs)로 전부 교체
3. 파일 맨 위 `NOTIFY_EMAIL`을 알림 받을 주소로 변경 (비워 두면 메일 알림 생략)

스크립트가 하는 일:

- `form` 값으로 탭을 고르고, 없으면 헤더와 함께 새로 만듭니다
- 전화번호를 숫자만 남겨 정규화하고 형식을 검증합니다 (`01X-XXXX-XXXX`)
- **같은 번호가 이미 있으면 행을 추가하지 않고** `{ ok: true, duplicate: true }`를 반환합니다
- `LockService`로 동시 제출 시 행이 겹쳐 쓰이는 것을 막습니다

## 3. 웹 앱으로 배포

1. 우상단 **배포 → 새 배포**
2. 유형 선택(톱니바퀴) → **웹 앱**
3. 설정
   - 설명: 아무거나 (예: `form v1`)
   - **실행 계정: 나(본인)**
   - **액세스 권한: 모든 사용자(Anyone)** ← 중요. 로그인 없이 폼이 POST 할 수 있어야 함
4. **배포** → 최초 1회 권한 승인(본인 구글 계정, "고급 → 안전하지 않음으로 이동" 거쳐 허용)
5. 발급된 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`) 복사

> 코드를 수정하면 매번 **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** 해야
> 반영됩니다. URL 은 그대로 유지됩니다.

## 4. 프로젝트에 연결

`.env` (없으면 `.env.example` 복사해서 생성):

```
PUBLIC_FORM_ENDPOINT=https://script.google.com/macros/s/.../exec
```

Vercel에 올릴 때도 같은 이름으로 환경 변수를 등록해야 합니다. `PUBLIC_` 접두사가 붙은 값은
빌드 시점에 클라이언트 번들로 인라인되므로, **빌드 전에 등록**되어 있어야 합니다.

값이 비어 있으면 폼은 콘솔 스텁으로만 동작(데이터 미전송)하므로 로컬 개발 중에는 비워 둬도
됩니다.

## 5. 확인

- 배포된 사이트(또는 `pnpm build && pnpm preview`)에서 폼 제출
- Google Sheet 에 행이 추가되는지 + 알림 메일 수신 확인
- 같은 브라우저는 `localStorage`(`deulli:applied`)로 중복 신청이 막히므로,
  재테스트 시 시크릿 창을 쓰거나 해당 키를 지우세요
- 웹 앱 URL을 브라우저에서 그냥 열면 `{"ok":true,"msg":"deulli form endpoint alive"}`가
  보여야 합니다 (GET 헬스체크)

## 운영 — 신청자에게 문자 보내기

시트의 `전화번호` 열을 그대로 복사해 문자 발송 서비스에 붙여 넣으면 됩니다. 값은
`010-1234-5678` 형태로 정규화되어 저장됩니다. (하이픈 없는 숫자만 넣으면 시트가 수로
해석해 맨 앞 `0`을 날려 버리기 때문에, 일부러 하이픈을 넣고 열 서식도 텍스트로 고정합니다.)

발송이 끝나면 **수집 목적이 소멸**합니다. 개인정보 처리방침에 적은 대로 해당 열을 파기하고,
파기 일자를 시트 어딘가에 남겨 두세요.

## 트러블슈팅

- **시트에 안 쌓임**: 배포 액세스 권한이 "모든 사용자"인지, 코드 수정 후 "새 버전"으로
  재배포했는지 확인
- **브라우저 콘솔에 CORS/전송 실패**: 드물게 응답 읽기가 막히면, `SignupForm.astro`의 `fetch`에
  `mode: "no-cors"`를 추가하는 대안이 있습니다(이 경우 응답을 못 읽으니 항상 성공으로
  간주 — 데이터는 정상 저장됨)
- **중복인데 성공으로 보임**: 의도된 동작입니다. 이미 신청한 번호를 다시 넣어도 사용자에게는
  완료 화면을 보여주고, 시트에는 행을 늘리지 않습니다
