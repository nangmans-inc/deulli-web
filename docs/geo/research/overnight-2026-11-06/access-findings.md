# 검색 접근과 인용 진단

## 실제 HTTP 확인

홈페이지와 소개 페이지에 일반 진단 User-Agent, OAI-SearchBot, ChatGPT-User, GPTBot, Googlebot 이름을 사용해 총 10개 요청을 보냈다. 모두 HTTP 200이며 경로별 응답 본문 해시가 같았다. robots.txt의 규칙도 각 경로 접근을 허용했다. 원자료는 `crawler-header-probes.json`이다.

이 요청은 이 컴퓨터에서 헤더를 바꿔 보낸 것이다. 검색봇의 검증된 IP로 요청한 것이 아니므로 실제 검색 인프라의 방화벽 통과나 색인 완료까지 입증하지 않는다. 반대로 특정 검색 도구에서 URL 열기가 실패했다고 전체 검색봇이 차단됐다고 결론 내리지 않는다.

## 공식 문서에 비춘 판단

[Google의 AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)는 AI Overviews와 AI Mode에 별도의 특수 최적화가 필요하지 않으며, 페이지의 색인·검색 스니펫 자격과 기본 SEO가 중요하다고 설명한다. robots·호스팅 접근, 내부 링크, 텍스트 본문, 화면 내용과 일치하는 구조화 데이터가 점검 대상이다. 특별한 AI 파일이나 별도 schema를 추가하는 것 자체가 노출 요건은 아니다.

[OpenAI의 크롤러 안내](https://developers.openai.com/api/docs/bots)는 검색용 OAI-SearchBot과 학습에 쓰일 수 있는 GPTBot의 제어를 구분한다. ChatGPT-User의 직접 방문은 검색 포함 여부를 결정하는 크롤링과 다르다. 따라서 URL을 지정한 진단에서 읽었다는 결과를 자연 검색 발견이나 모델 학습 완료로 해석하지 않는다.

## 다음 작업에 적용

- 현재 관측에서 robots 규칙 때문에 막혔다는 증거가 없어 규칙을 바꾸지 않았다.
- 새 AI 전용 파일을 필수 조건처럼 추가하지 않았다.
- 질문별로 읽을 수 있는 제품 설명·선택 안내·공식 콘텐츠 링크를 보강한다.
- Search Console 요청 접수와 실제 색인, API 인용과 소비자 AI 화면 인용은 각각 기록한다.
- 브라우저에서 새 ChatGPT·Gemini·Google 검색 화면은 도중에 빈 화면에 머물렀다. 해당 시도의 추가 답변이나 검색 순위를 수집했다고 기록하지 않았다. API 측정과 로컬 상태 화면은 별도로 정상 동작했다.

문서 확인일: 2026-11-06. 서비스의 공식 안내와 실제 관측 범위를 구분한 운영 진단이며, 순위 상승이나 자연 추천을 보장하는 판정은 아니다.
